# Blancall Windows 风险登记册（Phase 0）

- 评估基准：`Blancall-Std 7.6.1-NoAI / vc54`
- 产品范围：只做无 AI 版；无网络请求、无遥测
- 可能性/影响：高/中/低；「影响」指数据安全、功能可用性或发布阻断
- 每个风险必须有「早期信号」与「缓解/兜底」，不能只写「注意」

## 0. 最高优先级风险（先看这 6 条）

| 排名 | 风险 | 为什么致命 | 兜底 |
|---|---|---|---|
| 1 | R-03 备份导入语义差异导致误删 | 用户数据不可逆丢失 | 导入前预备份 + 更严校验 + 全量测试 |
| 2 | R-04 记录 id 复用导致墨迹错挂 | 静默错配，难发现 | `record_id_seq` + 回归测试 |
| 3 | R-05 JSON 字节/解析差异 | 文件被判损坏后覆盖 | 锁定 `org.json` + BOM/CRLF/稀疏字段 golden |
| 4 | R-02 手写一致率链 | 承诺 ≥99% 无法验证 | 固定画布/预处理/推理配置 + 300 条 golden |
| 5 | R-16 安装包体积超 120MB | 模型随包后体积压力更大 | jlink + 不捆绑素材 + 字体精简；必要时拆组件 |
| 6 | R-06 UI 重写量（6.3 万行） | 进度与质量失控 | 按页面分批 + 复用纯逻辑 + 明确 P0 边界 |

## 1. 数据与兼容

### R-01 中文手写模型许可

- **类别**：法律/分发
- **可能性**：确定（已存在）
- **影响**：高——权重训练数据 CASIA-HWDB 仅限学术，禁止商业使用；随包分发等同再分发。
- **证据**：`THIRD-PARTY-LICENSES:60-79`、`assets/hccr/release_metadata.json`。
- **已确认决策**：用户选择**随包分发**，接受该许可限制。
- **缓解**：
  1. README、关于页、安装向导、`THIRD-PARTY-LICENSES` 四处显著声明「仅限学术研究，禁止商业使用」。
  2. 不把模型用于任何商业发行；商用前需中科院授权或换数据重训。
  3. 安装包内单独目录 `models/`，许可文件随附。
- **早期信号**：用户要求商用/上架商店。
- **兜底**：改为可选组件或移除中文模型（英文模型许可清晰）。
- **状态**：已接受（法律风险仍在，需按上述声明执行）。**当前版本尚未随包模型**，Phase 5 实施时才触发再分发。

### R-02 手写一致率不达标

- **类别**：算法/体验
- **可能性**：中高
- **影响**：高——硬约束要求 top-1/top-5 ≥99%。
- **原因**：Android 识别链隐含依赖「视图像素尺寸 + 6px 绝对笔宽 + Canvas 抗锯齿」；桌面画布/字体/DPI 不同即漂移。
- **缓解**：
  1. 固定画布 1024×512、6px、白底黑笔、抗锯齿；两端用同尺寸回放。
  2. `preprocess.c` 原样编译；灰度 Rec.601 整数；不引入 mean/std。
  3. 冻结权重 sha256、NCNN 版本、线程数、fp16 开关（x64 建议关）。
  4. 300 条墨迹 golden，按字符/整词分别统计。
- **早期信号**：形近字 top1/top2 差值在 0.15 边界附近翻转；logits L∞ > 1e-4。
- **兜底**：明确标注「识别率未达 99%，手写为实验功能」；或只提供英文手写。

### R-03 备份导入误删/越界

- **类别**：数据安全
- **可能性**：中
- **影响**：极高——按类目整类替换 + 孤儿清理；Android 的 `files/.` 校验漏洞可写到数据目录之外。
- **缓解**：
  1. 导入前自动预备份（ADR-005）。
  2. 拒绝 `.`/`..`/空段/绝对路径/盘符/反斜杠/保留名/尾点/大小写冲突/重复条目。
  3. `keep` 集合覆盖 manifest 全部条目，不只 `files/` 前缀。
  4. 两段式 `.import` + 回滚；失败不碰正式文件。
  5. 攻击样本单测 + 真实 Android 包回归。
- **早期信号**：导入报告 `removed` 异常大；文件消失但无错误。
- **兜底**：从 `backups/pre-import_*.zip` 恢复；设置页提供「最近备份」。

### R-04 记录 id 复用导致墨迹/复习日志错挂

- **类别**：数据一致性
- **可能性**：高（Android 现状）
- **影响**：高——`ink/<recordId>.json`、`fsrs_reviews.jsonl.rid`、历史记录按 id 关联。
- **缓解**：
  1. 新增 `record_id_seq`，删除不回退；`max(cursor, maxId)+1`。
  2. 恢复备份后不降低游标。
  3. 测试：删除最大记录→重启→新 id 不复用；旧墨迹仍指向旧记录。
- **早期信号**：新记录出现旧墨迹缩略图；错题本引用不存在记录。
- **兜底**：提供「重建墨迹索引」工具（按记录时间/id 校验）。

### R-05 JSON 格式/解析差异

- **类别**：数据兼容
- **可能性**：高
- **影响**：高——文件被判损坏 → 回读 `.bak` → 下一次保存覆盖。
- **具体**：
  - BOM：所有 Store 不剥 BOM；Windows 编辑器可能写 BOM。
  - CRLF：JSONL 写入/读取；`records.json` 以 `[` 判旧格式。
  - 稀疏字段：空列表不写键、`-1` 哨兵不写。
  - `Float.toDouble()` 尾数（`0.8f` → `0.800000011920929`）。
  - `org.json` AOSP 与 Maven 实现差异（数字字符串/重复键/转义）。
- **缓解**：
  1. 写永远无 BOM、`\n`；读先剥 BOM。
  2. 锁定 `org.json:json:20240303`；禁止 `kotlinx.serialization` 直接读写。
  3. 复刻稀疏字段与 Float 语义；不做「补全」。
  4. 用真实 Android 文件做 golden；对同一文件做「读→写→读」幂等测试。
- **早期信号**：同一文件在两端读出的字段数不同；第二次启动后数据变化。
- **兜底**：只读模式 + 导出原始副本；修复前禁止写盘。

### R-06 UI 重写量失控

- **类别**：进度/质量
- **可能性**：高
- **影响**：高——UI 63,054 行 / 148 文件，且大量视觉细节。
- **缓解**：
  1. P0 只做闭环（首页/导入/列表/阅读/练习/单篇统计/设置子集）。
  2. 复用纯逻辑（判分、生成、统计、布局数据）；设计系统先做 12 个基础组件。
  3. 每页有验收清单；不做「像素级复刻」，保留品牌气质即可。
  4. 复杂图表先表格/简化图，Phase 3 再精修。
- **早期信号**：P0 页面反复返工；组件库被页面倒逼修改超过 3 次。
- **兜底**：冻结视觉范围，P2 延后。

### R-07 上游 Android 持续演进导致分叉

- **类别**：维护
- **可能性**：高
- **影响**：中高——算法/数据格式随 7.7、7.8 变化，Windows 落后。
- **缓解**：
  1. `tools/sync-from-android.ps1` + 变换清单 + 基线 commit。
  2. 每次同步跑全部 shared 测试与 golden。
  3. 数据格式变更必须同时更新 `DATA-FORMAT.md`。
- **早期信号**：Android 新增根文件/字段；备份 manifest 变化。
- **兜底**：锁定兼容版本（如 7.6.x），在 README 声明。

### R-08 记录文件体积/性能

- **类别**：性能
- **可能性**：中
- **影响**：中——50k 条记录 JSONL 全量解析，启动/内存压力。
- **缓解**：
  1. 启动后台加载；首页只读文章与必要聚合。
  2. 记录按 articleId 建区间索引，不复制整对象。
  3. 统计聚合缓存；滚动列表分页。
- **早期信号**：冷启动 >2s；内存 >400MB；列表滚动掉帧。
- **兜底**：惰性加载 + 限制首屏统计范围。

### R-09 时区/跨天/夏令时

- **类别**：算法一致性
- **可能性**：中
- **影响**：中——每日一句、连续天数、考试倒计时与 Android 不同。
- **缓解**：
  1. `DayBucket` 统一口径；`zone` 参数化。
  2. `FSRS` 同日判定加 `zone`（默认不变）。
  3. 测试固定 `Asia/Shanghai` 与 `UTC`。
- **早期信号**：跨天后句子卡不刷新/连续天数断。
- **兜底**：设置页显示「按本地时区计算」。

### R-10 随机 fuzz 导致 FSRS 到期不一致

- **类别**：算法一致性
- **可能性**：中
- **影响**：低——到期时间 ±5% 随机，属预期。
- **缓解**：文档说明；golden 用种子 RNG；不承诺逐毫秒一致。
- **早期信号**：同一张卡两端 due 不同但差距在 fuzz 范围。
- **兜底**：可关闭 fuzz（仅测试）。

## 2. 平台与体验

### R-11 中文 IME 在 Compose Desktop 的兼容性

- **类别**：输入
- **可能性**：中
- **影响**：高——中文用户无法正常作答。
- **缓解**：
  1. Phase 2 用 Microsoft Pinyin/搜狗实测。
  2. 关键输入框保留 `SwingPanel + JTextField` 降级路径。
  3. 记录 IME 组合事件，避免答案提交时丢字。
- **早期信号**：候选词不出现、组合串重复、回车误提交。
- **兜底**：全局切换 Swing 输入框。

### R-12 DPI/多显示器/字体渲染

- **类别**：体验
- **可能性**：中
- **影响**：中——125/150/200% 模糊、截断、窗口跑出屏幕。
- **缓解**：
  1. jpackage manifest `PerMonitorV2`；Compose/Skiko DPI 测试。
  2. 布局用 dp + 最小/最大宽度；文本不写死高度。
  3. 窗口位置夹到可见工作区。
- **早期信号**：切换显示器后窗口尺寸跳变；文本被裁。
- **兜底**：启动时重置窗口位置。

### R-13 提醒不可靠

- **类别**：系统集成
- **可能性**：高
- **影响**：中——Windows 无 WorkManager 等价物；应用未运行不提醒。
- **缓解**：
  1. 默认托盘常驻；启动/唤醒/跨天重算。
  2. 关闭按钮每次询问，用户可选择「最小化到托盘」；UI 明示「需保持应用运行」。
  3. Phase 6 评估计划任务（`--reminder`）作为可选。
  4. `reminder_state.json` 去重，防重复提醒。
- **早期信号**：睡眠唤醒后漏提醒；重复提醒。
- **当前状态**：`ReminderPlan/Schedule/StateStore` 已迁移并有测试；桌面 `ReminderScheduler`/设置 UI 尚未接入，所以当前版本不会主动提醒。
- **兜底**：启动时补发一次「今日待复习」通知。

### R-14 Toast/AUMID 注册失败

- **类别**：系统集成
- **可能性**：中
- **影响**：低——通知不显示或崩溃。
- **缓解**：优先托盘气泡（`Shell_NotifyIcon`）；Toast 失败静默降级；不因通知崩溃。
- **早期信号**：未注册 AUMID 时 `AppNotificationManager` 抛异常。
- **兜底**：应用内提醒条 + 托盘气泡。

### R-15 液态玻璃/动效观感落差

- **类别**：视觉
- **可能性**：高
- **影响**：低——不是功能 parity。
- **缓解**：静态半透明 + 高光 + 可选 Mica；保留圆角/留白/配色；设置可关闭动效。
- **早期信号**：用户反馈「不像原版」。
- **兜底**：提供「简洁模式」。

### R-16 安装包体积超 120MB

- **类别**：发布
- **可能性**：高（模型随包）
- **影响**：中——JRE + Skiko + 字体 + 22MB 中文模型。
- **缓解**：
  1. jlink 自定义运行时（去掉无用模块）。
  2. 不捆绑 philo/gaokao（20.7MB）；手写模型必需。
  3. 字体只留 Regular；图片/图标压缩；压缩资源。
  4. 安装包与便携包分别计量。
- **早期信号**：app-image 超 100MB；MSI 超 110MB。
- **当前状态**：尚未打包；已内置 `xwwk_regular.ttf`（3.4MB）用于 PDF，Skiko Windows runtime 约 10MB，PDFBox 依赖约 10MB。模型未随包，最终体积待 Phase 6 实测。
- **兜底**：把可选素材/字体拆为内容包；极端情况拆「精简版/完整版」，但模型默认随包不变。

### R-17 安装/卸载/升级丢数据

- **类别**：发布
- **可能性**：低
- **影响**：极高
- **缓解**：数据固定在 `%LOCALAPPDATA%\Blancall`，卸载不删；升级不触碰 `data/`；安装前自动备份；虚拟机全流程测试。
- **早期信号**：卸载脚本删除 LocalAppData；升级后文件缺失。
- **兜底**：安装包内置「恢复上一版本数据」说明。

### R-18 未签名安装包的 SmartScreen

- **类别**：分发
- **可能性**：确定（若无证书）
- **影响**：中——用户看到「未知发布者」，安装率下降。
- **缓解**：提供 SHA256、源码构建说明、VirusTotal 链接；README 说明。
- **早期信号**：用户反馈被拦截。
- **兜底**：购买代码签名证书（需用户决策）。

### R-19 单实例/多进程同时写数据

- **类别**：数据安全
- **可能性**：低
- **影响**：高——两个实例写同一文件。
- **缓解**：文件锁 + 回环激活；`AtomicFiles` 跨进程锁；写前检查锁。
- **早期信号**：第二实例未退出；`.tmp` 残留。
- **兜底**：检测到锁被占用时只读模式 + 提示。

## 3. 范围与合规

### R-20 误引入网络依赖/遥测

- **类别**：范围/隐私
- **可能性**：中
- **影响**：高——破坏「纯本地 NoAI」承诺。
- **缓解**：
  1. 禁止 HTTP 客户端依赖；CI 扫描 `java.net`/`okhttp`/`ktor`/`HttpURLConnection`。
  2. 安装包无 INTERNET 能力；抓包/防火墙验证。
  3. 代码评审检查新增依赖。
- **早期信号**：依赖树出现网络库；启动时有出站连接。
- **兜底**：移除依赖并回归；发布前必须通过零网络检查。

### R-21 Pro/AI 代码误入

- **类别**：范围
- **可能性**：中
- **影响**：中——出现 AI 入口/设置，破坏与 Std 的一致性。
- **缓解**：
  1. 只从 `Blancall-Std` 同步，不从 Pro 复制 `ui/ai`、`data/ai`、`Ai*` 文件。
  2. 路由/设置项清单与 Std 逐项对照。
  3. 测试断言无 `ai` 路由/设置 key。
- **早期信号**：同步脚本误把 Pro 文件带进来；设置页多出分组。
- **兜底**：删除并补守卫测试。

### R-22 素材库 WebView2 依赖/体积

- **类别**：扩展
- **可能性**：中
- **影响**：低——P2，可延后。
- **缓解**：优先内容包（纯文本/PDF），素材库内容页作为可选；WebView2 运行时检测，缺失提示安装。
- **早期信号**：目标机器无 WebView2。
- **兜底**：外部浏览器打开。

### R-23 6 套语言资源/plurals 迁移错误

- **类别**：i18n
- **可能性**：中
- **影响**：中——文案缺失/占位符错位/俄语复数错误。
- **缓解**：构建期生成 + 守卫测试（key/占位符/plurals）；运行时格式化测试；抽样人工校对。
- **早期信号**：界面出现 `%1$s` 或空白。
- **兜底**：回退简中并记录缺失 key。

### R-24 PDF 字体/布局回归

- **类别**：导出
- **可能性**：中
- **影响**：中——中文缺字/断行错/答案页错位。
- **缓解**：嵌入 OFL 字体子集；`PDFont.getStringWidth` 度量；golden 文本快照；在其他机器打开验证。
- **早期信号**：PDF 中文字变方框；行宽溢出。
- **兜底**：改用系统字体并提示「仅本机可用」。

### R-25 许可证合规缺口

- **类别**：法律
- **可能性**：中
- **影响**：中——commonmark BSD-2 未列入 THIRD-PARTY；NCNN/字体声明缺失；手写模型声明不足。
- **缓解**：Windows 的 `THIRD-PARTY-LICENSES` 完整列出；保留版权头；模型单独声明并随包附许可。
- **早期信号**：发布审查发现缺声明。
- **兜底**：补录后再发布。

### R-26 用户期望「手机体验 1:1」

- **类别**：产品
- **可能性**：中
- **影响**：中——手势/小组件/液态玻璃差异。
- **缓解**：README 明确桌面设计原则（键鼠优先、信息密度）；引导页展示桌面快捷方式；不做手机手势硬套。
- **早期信号**：反馈「为什么不能左右滑」。
- **兜底**：提供可选触控手势（Phase 3 后）。

### R-27 测试数据缺失导致「假对齐」

- **类别**：验证
- **可能性**：中
- **影响**：高——只跑合成数据，真实文件一导入就坏。
- **缓解**：必须用真实 Android `filesDir` 副本与备份 ZIP 做 golden；脱敏可选；测试数据不入库。
- **早期信号**：合成测试全绿但真实导入失败。
- **兜底**：先修兼容再继续功能。

## 4. 已确认决策与剩余假设

### 已确认（Phase 0）

1. 技术栈：**Compose Multiplatform Desktop（Kotlin/JVM）**。
2. 产品范围：**只做无 AI 版**，与 `Blancall-Std` 对齐；无网络、无遥测。
3. 手写模型：**随包分发**；接受 CASIA-HWDB 仅学术、禁商用的限制，并在四处显著声明。
4. 关闭按钮：**每次询问**（最小化到托盘/退出/记住选择）。

### 假设

1. 用户使用 Windows 10 22H2+ / Windows 11 x64；arm64 不承诺。
2. Android 数据通过备份 ZIP 或直接复制 `filesDir` 迁移；不支持云同步。
3. Android 上游在 Phase 1-3 期间不会发生破坏性数据格式变更；若发生，按 R-07 处理。
4. 不要求与 Android 的 UI 像素级一致，只要求功能与数据对等。
5. 首次发布可以无代码签名证书（提供 SHA256 + 说明）。
